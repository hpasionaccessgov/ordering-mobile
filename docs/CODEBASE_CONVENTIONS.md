# Cafébara mobile — codebase conventions

Reference for humans and agents. Keep the app thin: UI renders, services talk to the backend, the
backend owns all business rules.

## Stack / layout

- **App**: Ionic React 9, React 19, TypeScript (strict), Vite 8.
- **Native**: Capacitor 8, Android shell in `android/` (generated by `npx cap add android`).
- **State**: React hooks + `AuthContext`. No Redux, no global store library.
- **Backend**: Cafébara REST API; contract in `docs/API.md`, canonical doc at `ordering_system/docs/API.md`.

## Naming

| Kind | Convention | Example |
|---|---|---|
| Screen | PascalCase + page suffix, default export | `src/pages/ProductDetail.tsx` |
| Component | PascalCase file and export, no default barrel | `src/components/StatusBadge.tsx` |
| Service | camelCase file, named function exports | `src/services/cartService.ts` |
| Type | PascalCase interface in `src/services/types.ts` | `OrderItem`, `CartSummary` |
| Context | `<Name>Context.tsx`, exports `<Name>Provider` + `use<Name>` | `AuthContext.tsx` |
| CSS class | `cafebara-<part>` | `cafebara-product-card` |
| Icon | camelCase named export from `ionicons/icons` | `cartOutline` |
| Feature node | kebab-case slug matching frontmatter | `features/order-tracking.md` |

## Screens

- One route → one screen in `src/pages/`. Keep screens as orchestration: load, hold state, render.
- Structure: `IonPage` → `AppHeader` → `IonContent`. Use `StateViews` for loading/error/empty.
- Data loading: `useIonViewWillEnter` for enter-time fetch; `IonRefresher` for manual refresh.
- Never duplicate fetch logic in a screen; call a function from `src/services/*`.
- Every exported component needs an explicit `React.JSX.Element` return type (eslint rule).

## Services and data

- `src/services/api.ts` is the only place that calls `fetch`. It adds the bearer token, unwraps
  `{success, data, meta}` and throws `ApiError`.
- All other services import `request`/`requestPage` and expose one function per API call.
- Server prices are decimal strings. Format at the edge: `Number(value).toFixed(2)`.
- Timestamps are Unix seconds: `new Date(value * 1000).toLocaleString()`.
- Token lives in Capacitor Preferences under `cafebara.auth.token`; only `tokenStorage.ts` touches it.
- A 401 from `request()` removes the token and dispatches `cafebara:unauthorized`; `AuthProvider` clears the user.

## Components and theme

- Reuse `AppHeader`, `StateViews`, `ProductCard`, `StatusBadge` before creating a component.
- `IonItem` has no `fill` prop; put `fill="outline"` on `IonInput` instead.
- Theme tokens live in `src/theme/variables.css` (Cafébara brown/cream); screen layout in `app.css`.
- Prefer Ionic components and CSS variables over custom CSS.

## Navigation

- All route paths are declared in `src/App.tsx`. Protected screens are children of `RequireAuth`.
- Navigate with `routerLink` or `useNavigate`. Never `window.location` or raw hash changes.
- Tab bar entries must match an existing route path.

## Native

- Change `capacitor.config.ts` → `npm run build` → `npx cap sync android`.
- `android/gradle.properties` pins JDK 21 (Capacitor 8 requirement); `android/local.properties` points at the local SDK.
- Do not hand-edit `android/app/src/main/assets/public/` — `cap sync` overwrites it.
- `cafebara/` is a separate user repo; never reformat or overwrite it.

## Before finishing

1. Can an existing component/service/hook be reused with a prop?
2. Did every new exported function get an explicit return type?
3. Is every API call behind a service function?
4. Did the feature map node(s) and base row(s) get updated?
5. Run `npm run lint`, `npm run test:unit`, `npm run build`.
